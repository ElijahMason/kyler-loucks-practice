Route card

Set the route before you move.

A deploy is a route across blocks. Kyler Loucks draws that route. The pipeline is the path that can show a proceed aspect. A change made from a laptop, outside the pipeline, is a hand signal, and the board does not treat a hand signal as the route.

  1. 01

    Put the change in the repository

    Source control is block 1. If the change is not there, the route has not started.

  2. 02

    Make the plan readable

    Infrastructure is code. Terraform belongs here when the platform is expressed as code a second person can review. The plan names the diff before apply.

  3. 03

    Let interlocking hold conflicts

    Two routes into one block cannot both be clear. An unnamed environment, a second account strategy, or a bill you cannot read holds the route at stop.

  4. 04

    Apply on the lined path

    CI/CD carries the change. GitOps belongs when production should follow the repository. Apply waits until the previous block has released.

  5. 05

    Keep watch occupied

    The route includes the time after apply. Reliability is the watch on that block, hired as a review when you want the failure modes named.
